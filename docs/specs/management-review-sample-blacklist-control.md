# 管理页复核、样本库与官方拉黑控制增量规格

## Problem Statement

当前本机管理页已经能够展示证据、样本版本和官方拉黑队列，但这几个核心工作流仍然把内部实现状态直接暴露给用户：证据必须逐条展开后才能操作，展开后会一次性铺开大量评论；样本版本只显示数量和样本 ID，无法确认具体内容；新版本可能只包含本次新增的一条样本，旧样本不会自动进入当前 AI 输入；拉黑队列直接显示英文选择器错误，用户无法判断发生了什么或下一步该做什么。

此外，本地隐藏和官方拉黑目前缺少一个清晰的总控制。用户希望默认只执行立即生效的本地隐藏，只有显式开启“自动执行官方拉黑”后，新的命中结果才进入官方拉黑队列，且已有队列可以保留、暂停和继续处理。

## Solution

将管理页改造成面向连续复核的工作台，并补齐样本版本、队列错误和官方拉黑开关的完整语义：

- 证据页采用“复核收件箱 + 密集列表 + 桌面端右侧详情检查器”。列表负责识别、比较和高频操作；检查器负责完整评论、楼层上下文、模型理由和低频操作。用户不打开详情也可以完成主要复核动作，打开详情后不会丢失列表位置。
- 样本版本继续保存为不可变快照。历史版本及其样本内容保留，只有最新已发布版本参与 AI 分析。创建新版本时默认继承当前生效版本，再追加本次导入或复核样本，并按样本类型和标准化文本去重。
- 拉黑错误由稳定的机器错误类型转换为中文用户说明、停止原因和恢复动作；原始英文错误放入按需查看的技术详情，不再作为唯一主提示。
- 增加持久化的“自动执行官方拉黑”总开关。默认关闭时仍立即本地隐藏命中 UID，但不创建新的官方拉黑任务，后台也不消费已有待处理队列；开启后才处理新任务和已排队任务。本地隐藏状态与官方拉黑状态始终分开表达。

## User Stories

1. 作为复核用户，我希望在不展开证据的情况下看到 UID、昵称、判定、置信度、评论摘要和命中信号，以便快速决定下一步。
2. 作为复核用户，我希望每行直接提供主要动作，以便连续处理多个证据而不反复打开和关闭详情。
3. 作为复核用户，我希望查看完整评论和上下文时保留当前筛选、滚动位置和选中对象，以便检查后继续原来的复核流程。
4. 作为复核用户，我希望详情检查器显示完整评论原文、根评论、楼中楼上下文、来源视频、评论链接、模型理由、置信度、模型版本和样本版本，以便判断证据是否充分。
5. 作为复核用户，我希望 AI 结果和人工复核状态分开显示，以便区分模型意见与我已经做出的处理。
6. 作为复核用户，我希望把例外、样本标记等低频操作放入明确标记的“更多”菜单，以便列表不被低频按钮挤满。
7. 作为复核用户，我希望单项操作只锁定当前行，并显示处理中、成功和可重试失败，以便其他证据仍可继续处理。
8. 作为复核用户，我希望批量操作显示准确的选中数量和影响范围，以便确认不会误操作不可见对象。
9. 作为复核用户，我希望复核历史与待处理收件箱分开，以便历史记录不会干扰当前待办。
10. 作为复核用户，我希望看到当前生效的样本版本，以便知道后续 AI 分析实际会使用哪一套样本。
11. 作为复核用户，我希望历史样本版本及正文继续保留，以便追溯过去的分析依据。
12. 作为复核用户，我希望样本版本行显示版本、类型、状态、数量、创建时间和发布时间，以便快速比较不同版本。
13. 作为复核用户，我希望样本版本直接显示少量正文预览，以便不用打开详情就能判断版本内容。
14. 作为复核用户，我希望通过“查看全部样本”查看某个版本的完整正文、标签和来源，以便复核样本质量。
15. 作为复核用户，我希望新版本默认带上当前版本已有样本，再追加新内容，以便增加一条样本不会意外丢失整个样本库。
16. 作为复核用户，我希望发布前按样本类型和文本去重，以便重复导入不会扩大无效上下文。
17. 作为复核用户，我希望历史任务继续引用它当时使用的样本版本，以便新版本不会改写过去的分析证据。
18. 作为复核用户，我希望样本状态使用“草稿”“当前生效”“历史版本”等可读名称，以便不必理解内部枚举。
19. 作为队列用户，我希望拉黑错误先说明发生了什么、为什么暂停和怎么恢复，以便看到错误后可以采取行动。
20. 作为队列用户，我希望页面把登录失效、验证码、页面结构变化、浏览器环境故障和临时网络错误区分开，以便选择正确的恢复方式。
21. 作为队列用户，我希望原始错误、错误类型、尝试次数和时间可以在技术详情中查看，以便需要排障时仍有足够证据。
22. 作为队列用户，我希望错误发生后 UID、队列项、状态和重试/恢复动作仍然保留，以便失败任务不会从列表中消失。
23. 作为用户，我希望“自动执行官方拉黑”默认关闭，以便安装后不会立即开始官方动作。
24. 作为用户，我希望关闭总开关时命中 UID 仍立即本地隐藏，以便本地过滤不依赖官方拉黑。
25. 作为用户，我希望关闭总开关时不创建新的官方拉黑任务，以便“只隐藏”真正只影响本地。
26. 作为用户，我希望关闭总开关时已有待处理队列不被删除或取消，以便重新开启后可以继续处理已收集的任务。
27. 作为用户，我希望关闭总开关时后台 Worker 不消费队列，以便官方动作确实处于停止状态。
28. 作为用户，我希望开启总开关后新命中 UID 才进入官方队列，已排队任务可以继续处理，以便官方动作有明确的启用边界。
29. 作为用户，我希望已经暂停、失败或阻断的任务不会因为打开开关而被静默重试，以便错误恢复仍然是可控动作。
30. 作为用户，我希望开关状态在服务重启后保持，以便不必每次重新确认执行策略。
31. 作为用户，我希望页面明确区分“本地隐藏已生效”“官方拉黑已排队”和“官方拉黑已完成”，以便不把本地结果误认为平台结果。
32. 作为用户，我希望 Dashboard 只展示自动拉黑状态，拉黑队列页面拥有唯一控制入口，以便不会出现两个含义不同的总开关。
33. 作为开发者，我希望任务编排、样本管理和队列 API 都能通过固定替身验证，以便不依赖真实 B 站账号测试主要状态行为。
34. 作为开发者，我希望模型、采集器和拉黑执行器的失败都能形成可观察的事件和分析尝试，以便用户不再面对“提交后不知道发生了什么”的黑盒状态。

## Implementation Decisions

- 该规格是现有 B 站评论过滤主规格的增量，沿用本机优先、SQLite 权威、UID 作为唯一键、评论区范围和远程 OpenAI-compatible 模型边界。
- 证据工作台采用列表与详情分工：列表只保留识别、比较、状态和高频操作所需的信息；完整证据、模型解释、来源和历史放入详情检查器。
- 桌面端详情检查器固定在右侧；窄屏时改为覆盖层或堆叠区域。详情关闭后必须回到原列表位置和原筛选快照。
- 证据行的主要动作保持可见；例外、标记样本和其他低频管理动作进入带文字的“更多”菜单。动作名称必须描述真实副作用：确认官方拉黑、仅本地隐藏、撤销、加入例外和标记样例不得混用。
- AI 结果 `hit` / `uncertain` 与人工状态 `pending` / `confirmed` / `local-only` / `revoked` / `exception` / `sampled` 分开保存和展示。
- 证据行、样本行和队列行都采用局部状态更新，不因单项请求遮罩或清空整个页面。请求失败时保留对象、筛选、滚动位置和已输入内容。
- 样本版本是不可变快照。发布新版本会使旧的已发布版本变为历史版本，但不会删除版本记录、样本记录或历史任务使用的版本。
- 分析器只读取最新已发布版本。历史版本不自动拼接到当前分析输入；只有创建新版本时，才将当前生效样本复制到新快照并追加本次样本。
- 新版本合并按样本类型和标准化文本去重；空文本丢弃；重复数量可以作为辅助反馈显示，但不能替代正文展示。
- 样本管理接口需要返回可供管理页展示的完整样本项、标签、来源、版本状态、创建/发布时间和当前生效标记。样本 ID 只作为复制和排障信息。
- 样本库页面需要提供版本列表、当前生效提示、正文预览和完整样本详情。发布草稿后更新原列表行，不导航到无关页面。
- 队列错误采用稳定的错误分类、用户说明、恢复动作和技术详情四层信息。未知错误也必须有可读兜底文案，不能直接把内部英文作为唯一提示。
- 当前“未找到 B 站确认按钮”属于页面结构/拦截类错误：队列项进入暂停状态，主提示说明 B 站确认结构未识别；技术详情保留原始 selector 错误、失败类型、尝试次数和时间。
- 登录态失效、验证码/风控页面和明确平台拦截进入暂停；暂时性网络或执行环境错误按既有可重试规则进入失败或重试状态。页面必须显示对应的恢复动作。
- 新增本机设置存储，持久化布尔值 `auto_blacklist_enabled`，默认值为 `false`。设置读写属于服务端权威状态，不依赖浏览器临时状态。
- 提供自动拉黑设置的读取和更新管理接口。更新响应必须返回当前开关值、当前执行模式和持久化成功后的时间或版本信息。
- 开关关闭时：命中和不确定结果仍更新本地隐藏名单和证据；新的官方拉黑任务不创建；已有队列项保留；后台 Worker 不领取新的队列项。
- 开关开启时：新命中结果可以创建官方拉黑任务；已有 `queued` 队列项可以继续消费。本规格不要求打开开关时自动重试已经 `paused`、`failed`、`blocked` 或 `cancelled` 的任务。
- 开关关闭期间产生的仅本地隐藏 UID 不自动回填官方队列；如果将来需要补入队列，应提供独立的、明确范围的批量动作，不隐藏在开关切换副作用中。
- 自动拉黑开关唯一放在拉黑队列页面的全局操作区；Dashboard 只展示只读状态。关闭状态文案为“已关闭 · 仅本地隐藏”，开启状态文案为“已开启 · 命中后排入官方拉黑队列”。
- Worker 的消费门控必须位于队列领取边界，而不是只在前端隐藏按钮；即使管理页未打开，开关语义也必须成立。
- 任务事件和分析尝试继续作为可观察记录，至少覆盖任务创建、采集开始/进度/结束、分析开始/批次/失败/结束、名单应用和队列创建/暂停/完成。
- 本规格不改变评论采集范围、弹幕范围、AI 批量策略、模型供应方式、UID 本地隐藏机制或后台 Chromium 的无窗口约束。

## Testing Decisions

- 测试以外部行为、持久化状态、API 响应和管理页可见语义为准，不测试函数调用顺序、CSS 具体实现或内部 selector 的组织方式。
- 最高测试 seam 是现有管理 API 与视频任务编排入口的组合：使用内存数据库、固定采集器、固定分析器和记录型拉黑执行器，从任务输入一路验证本地名单、证据、样本版本、开关和队列输出。
- 样本管理测试覆盖：创建包含旧样本的新草稿、按类型和文本去重、发布后旧版本停用、旧版本正文仍可读取、当前分析只得到最新完整快照、历史任务继续保留原样本版本。
- 样本管理 API 测试覆盖：版本列表、正文预览所需字段、完整样本详情、草稿发布、当前生效标记和错误状态。
- 自动拉黑设置测试覆盖：默认关闭、更新后重启仍保持、关闭时命中只产生本地隐藏而没有新队列、关闭时已有 `queued` 项不被消费、开启后 `queued` 项可消费、暂停/失败项不会被静默重试。
- 队列错误测试使用记录型执行器抛出页面结构变化、认证失效、验证码/拦截和临时错误，验证队列状态、机器分类、中文用户提示和可恢复动作；原始错误只能出现在技术详情字段。
- 证据工作台前端测试覆盖：列表默认显示主要判断字段、主要操作无需展开、详情检查器保留选中对象、筛选和滚动上下文、单项 busy/success/error、批量选择数量和状态语义。
- 任务可观察性测试覆盖：部分采集仍能进入分析、没有可分析评论才跳过分析、非法模型响应能形成失败尝试、分析失败不会伪造完成状态、阶段事件可以按顺序读取。
- 现有单元测试和管理 API 测试作为先例；真实 B 站只使用明确授权的测试账号和小规模数据做适配验证，不把验证码、风控页面或实时页面结构作为自动化单元测试依赖。

## Out of Scope

- 不采集、分析或隐藏弹幕。
- 不支持动态、直播、番剧、移动端、App 或其他平台。
- 不增加 LM Studio、本机桌面 LLM 或其他本地模型运行时支持。
- 不改变远程 OpenAI-compatible 接口的批量分析协议，不在本规格内重写模型提示词或重新设计判定规则。
- 不对历史任务自动回溯重判；新样本版本只影响后续任务。
- 不因为关闭后重新开启自动拉黑而自动把关闭期间所有本地隐藏 UID 批量补入官方队列。
- 不自动重试已经暂停、失败、阻断或取消的官方拉黑任务。
- 不通过隐藏接口、伪造请求、更换身份、代理池或其他方式绕过 B 站验证和反自动化控制。
- 不在本规格内重做既有颜色、字体、品牌语气和整体视觉 token；只实现已记录的页面信息架构、状态和动作语义。
- 不把原始数据库 ID、内部枚举或英文实现错误作为普通用户的主要信息。

## Further Notes

- 现有主规格和早期票据中“官方拉黑默认自动消费”的表述，需要在实现本规格时以本规格的总开关语义为准：默认关闭，开启后才执行官方拉黑。
- 已确认的词条和友军例外继续沿用： “巴斯特”“䟋”“天龙八部”“粘慕斯”，以及“曼巴斯特”例外；昵称命中依据整体语义，不是简单子串。
- 证据布局和样本/队列控制方案已经记录在项目 `design-spec.md` 的第 13、14 节；本规格将其转化为可实现、可测试的任务边界。
- 本轮只产出规格并发布 issue，不修改业务代码；实现前应保留工作树中已有的用户改动。
