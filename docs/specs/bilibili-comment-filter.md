# B 站评论过滤工具规格

## Problem Statement

用户在 B 站浏览视频时，经常遇到集中出现的詹黑评论。手工识别评论作者、逐个记录 UID、隐藏评论和执行账号拉黑都很耗时，尤其是评论区规模较大、楼中楼较深或同一账号在多个视频重复出现时。

用户需要一个面向个人账号的工具：从用户选定的 B 站普通视频开始，优先完整采集评论区；即使采集因接口或平台原因不完整，只要已有可分析评论，也继续使用 AI 识别高召回的詹黑 UID，并明确标记任务为部分完成。识别结果立即在浏览器中隐藏对应 UID 的评论；只有在“自动执行官方拉黑”总开关开启时，明确命中的 UID 才进入 B 站拉黑队列。用户还需要能够回看已保存证据、纠正判定、维护样本，并把复核结果沉淀为后续分析的参考。

## Solution

提供一个 Chrome/Edge Manifest V3 浏览器插件和一个本机优先的后台服务。

插件负责从当前已登录的 B 站普通视频页提交视频任务、同步当前登录态，并在评论区渲染过程中依据全局 UID 名单隐藏评论和楼中楼回复。本机服务负责异步采集评论、保存任务和证据、按 UID 组织评论上下文、调用可配置的远程 OpenAI-compatible 分析端点、更新全局 UID 名单、提供复核管理页，以及持续消费官方拉黑队列。

AI 使用用户提供的评论正例、反例、显著詹黑样例、詹黑型昵称样本和友军例外识别表达语义。分析默认采用高召回策略：明确命中立即本地隐藏；总开关开启时同时进入官方拉黑队列，关闭时仅保留本地隐藏；不确定结果也立即本地隐藏，但只进入复核，不自动拉黑。

## User Stories

1. 作为 B 站用户，我希望在普通视频页选择当前视频提交分析任务，以便不必手工复制视频地址。
2. 作为 B 站用户，我希望插件从当前登录浏览器同步会话，以便不必在后台工作实例中重复登录。
3. 作为 B 站用户，我希望提交任务后可以关闭当前视频页，以便完整采集和分析在后台继续进行。
4. 作为 B 站用户，我希望看到任务的采集、分析、汇总和完成状态，以便知道系统是否仍在工作。
5. 作为 B 站用户，我希望任务在网络错误后自动重试，以便暂时性接口失败不需要我重新提交视频。
6. 作为 B 站用户，我希望任务在断点处恢复，以便大评论区不因进程重启而从头采集。
7. 作为 B 站用户，我希望看到采集数量、评论总量、楼中楼数量和覆盖率，以便知道结果是否完整。
8. 作为 B 站用户，我希望一级评论、楼中楼回复和置顶评论都被纳入采集，以便不会因为评论层级而漏掉目标账号。
9. 作为 B 站用户，我希望同一 UID 的评论在一个视频任务中被归并，以便 AI 可以判断该账号的整体表达，而不是孤立判断每条评论。
10. 作为 B 站用户，我希望评论带有父评论、根评论和同楼回复上下文，以便引用、反驳和反讽有机会被正确理解。
11. 作为 B 站用户，我希望 AI 以批次而不是每条评论一次的方式分析，以便减少调用次数、成本和任务延迟。
12. 作为 B 站用户，我希望短评论区可以在一批中完成分析，以便小任务快速得到结果。
13. 作为 B 站用户，我希望大评论区按当前模型实际 token 预算拆分，以便长上下文不会导致请求截断或任务失败。
14. 作为 B 站用户，我希望样本版本默认完整注入分析批次，以便我提供的样本都能影响模型判断。
15. 作为 B 站用户，我希望在样本和评论超过模型上下文限制时自动降级为相关样本或压缩摘要，以便任务仍能继续且不会静默截断。
16. 作为 B 站用户，我希望模型识别明确针对詹姆斯的侮辱、恶意贬损、持续嘲讽和明显敌意，以便高召回地筛选目标账号。
17. 作为 B 站用户，我希望模型识别“巴斯特”“䟋”“天龙八部”“粘慕斯”等已知表达，以便常见的詹黑黑话不会依赖模型临时猜测。
18. 作为 B 站用户，我希望“曼巴斯特”等已知友军表达覆盖词条例外，以便相似字符串不会被简单子串规则误判。
19. 作为 B 站用户，我希望昵称整体语义可以作为硬规则信号，以便明显表达詹黑身份的账号不需要等待评论内容分析。
20. 作为 B 站用户，我希望可以导入詹黑评论正例、正常批评反例、友军表达和詹黑型昵称样本，以便模型学习我认可的语境边界。
21. 作为 B 站用户，我希望初始昵称样本可以只有正例，以便不必为了启动工具而人工构造完整反例集。
22. 作为 B 站用户，我希望复核时可以把评论标记为显著詹黑样例，以便高质量正例立即参与后续分析和评测。
23. 作为 B 站用户，我希望样本可以通过文本框或文件导入，并在发布前预览和去重，以便维护样本不需要手工编辑数据库。
24. 作为 B 站用户，我希望 AI 输出命中、非目标和不确定三种结果，以便区别明确判定与需要复核的边界情况。
25. 作为 B 站用户，我希望命中 UID 立即加入本地隐藏名单，以便不必等待官方拉黑完成就能停止看到相关评论。
26. 作为 B 站用户，我希望不确定 UID 也立即本地隐藏，以便高召回策略优先减少漏放目标账号。
27. 作为 B 站用户，我希望不确定 UID 不自动进入官方拉黑队列，以便可以先复核边界账号。
28. 作为 B 站用户，我希望 UID 名单以 B 站 UID 为唯一键，以便昵称变化不会使历史过滤失效。
29. 作为 B 站用户，我希望昵称只作为当前展示快照保存，以便能看到当时模型判断使用的昵称。
30. 作为 B 站用户，我希望本地隐藏名单跨视频全局生效，以便被识别的 UID 在其他视频评论区也立即隐藏。
31. 作为 B 站用户，我希望播放器弹幕在首版不被采集、不被分析也不被隐藏，以便首版边界保持在评论区。
32. 作为 B 站用户，我希望只在普通视频页使用过滤功能，以便动态、直播、番剧、移动端和 App 不会产生未验证的行为。
33. 作为 B 站用户，我希望命中和不确定结果保存完整评论原文、楼层上下文、来源视频和评论链接，以便闲暇时可以回看判定依据。
34. 作为 B 站用户，我希望看到命中的词条、昵称样本、模型理由、置信度、时间和模型版本，以便能解释每个 UID 为什么被处理。
35. 作为 B 站用户，我希望复核页面可以确认官方拉黑、撤销、仅本地隐藏、加入例外和更新样本，以便修正误判并持续改进工具。
36. 作为 B 站用户，我希望撤销操作能恢复本地显示并取消未执行的拉黑任务，以便复核结果可以真正改变后续动作。
37. 作为 B 站用户，我希望把 UID 标记为例外后可以阻止未来同类规则自动重新命中，以便友军账号不会反复进入名单。
38. 作为 B 站用户，我希望开启自动执行开关后官方拉黑队列在明确命中后自动生成，以便不需要手工复制 UID。
39. 作为 B 站用户，我希望官方拉黑队列可以后台顺序执行、暂停、恢复和重试，以便大批量任务不需要我守在电脑前。
40. 作为 B 站用户，我希望官方拉黑成功后 UID 状态变为 blocked，以便我能区分本地隐藏和 B 站账号状态。
41. 作为 B 站用户，我希望拉黑队列遇到登录失效、验证码或明确平台拦截时暂停并报告，以便异常不会被无限重试。
42. 作为 B 站用户，我希望官方拉黑队列失败后保留原状态，并由我显式点击“重试”或“恢复”，以便普通故障不会在我不知情时重复执行。
43. 作为 B 站用户，我希望后台工作实例使用独立配置，不弹窗、不抢焦点、不捕获键鼠输入，以便游戏和办公不受影响。
44. 作为 B 站用户，我希望后台实例只在有任务时运行，队列为空后退出，以便空闲时不持续占用资源。
45. 作为 B 站用户，我希望可以通过配置远程 OpenAI-compatible 分析端点，以便根据效果和成本选择模型。
46. 作为 B 站用户，我希望本机管理页可以查看视频任务、UID 名单、证据、样本、复核记录和拉黑队列，以便不依赖插件弹窗处理复杂工作。
47. 作为 B 站用户，我希望插件弹窗只承担提交当前视频、显示状态和连接状态，以便浏览器端保持简单。
48. 作为 B 站用户，我希望后台 SQLite 是名单权威、插件只保存同步缓存，以便撤销和跨视频状态不会出现两套结果。
49. 作为 B 站用户，我希望插件在服务断开时仍能使用已同步 UID 缓存隐藏评论，以便短暂断连不立即暴露已知账号。
50. 作为 B 站用户，我希望本机服务可以一键启动，并支持 Docker Compose 部署，以便按个人机器或后续云端环境选择部署方式。

## Implementation Decisions

- 产品由 Chromium Manifest V3 插件和本机优先的 Python 服务组成；服务层保留云端部署能力，但首版默认在本机运行。
- 服务使用 SQLite 作为持久化权威，保存视频任务、评论证据、样本版本、全局 UID 状态、复核记录和拉黑队列；插件只缓存可用于本地过滤的 UID 状态。
- 本机管理页负责复杂查询、复核和队列管理；插件弹窗负责当前视频提交、连接状态和任务状态；页面内容脚本负责评论 DOM 的 UID 识别和隐藏。
- 首版只处理已登录 Chrome/Edge 桌面普通视频页的评论区和楼中楼。弹幕不采集、不分析、不隐藏；动态、直播、番剧、移动端和 App 不在范围内。
- 插件从当前登录浏览器读取 B 站会话，并通过本机接口同步给采集服务和独立 Chromium 工作实例；后台实例不要求用户二次登录。
- 插件在打开弹窗读取状态、安装、浏览器启动和已有的定时 UID 同步时，会在存在 B 站标签页的前提下后台同步登录态；没有 B 站标签页时不读取 Cookie。
- 视频提交创建一个独立视频任务。任务异步执行评论采集、批量 AI 分析、UID 汇总、证据写入和名单更新，支持进度、断点、重试、暂停和恢复；采集不完整但已有评论时继续分析并保留 `partial` 状态，没有可分析评论时才不启动 AI。
- 评论采集器必须处理一级评论、楼中楼、置顶评论、分页和完整性统计，并记录采集覆盖率、失败页和恢复状态。采集器可参考 `bbc-skill` 的分页、嵌套回复、断点和完整性设计，但不把外部仓库作为唯一运行依赖。
- AI 分析以 UID 为组织单位：每个 UID 的昵称、评论、评论 ID 和楼层上下文组成账号包；账号包按模型实际 token 预算批量发送，而不是每条评论单独调用。
- 短评论区可以单批处理；大评论区动态拆批。对不确定结果可以进行第二轮小范围分析，名单去重和 UID 聚合由本地代码负责。
- 样本版本默认完整注入每个分析批次；如果当前模型实际上下文不足，才切换到相关样本或压缩摘要，并记录降级方式。
- AI 接口仅采用可配置的远程 OpenAI-compatible 分析端点；桌面端自托管模型不在当前范围内。模型输出必须结构化表达 UID、三态判定、证据引用、信号、理由、置信度、模型版本和样本版本。
- 判定三态为 `命中`、`非目标` 和 `不确定`。`命中`立即本地隐藏，并在自动执行官方拉黑开关开启时创建官方拉黑任务；`非目标`不更新全局 UID 名单；`不确定`立即本地隐藏并进入复核，不自动拉黑。
- 高召回策略优先于保守过滤。明确昵称语义、已确认词条和模型结果共同决定命中；友军例外优先于宽松词条，但上下文不确定时仍允许进入 `review`。
- `B 站 UID` 是所有名单、去重、同步、证据和队列操作的唯一主键；昵称保存为可变展示快照。
- 全局 UID 状态包括 `hidden`、`review`、`queued`、`blocked`、`exception`、`failed` 和 `paused`。视频任务独立分析，任何任务产生的明确命中都更新全局本地隐藏名单。
- 命中和不确定结果保留完整评论原文、楼层上下文、来源视频、评论链接、昵称快照、命中信号、模型理由、时间和版本；非目标评论只保留任务统计。
- 复核操作包括确认、撤销、仅隐藏、加入例外、加入正例、加入显著詹黑样例和更新规则。显著样例发布后立即参与后续分析，但不回溯改写历史任务。
- 官方拉黑队列仅在自动执行官方拉黑总开关开启时自动消费，使用独立 Chromium 工作实例完成 B 站可见原生界面操作，不调用隐藏接口、不伪造请求、不绕过验证。工作实例无弹窗、不抢焦点、不捕获键鼠输入，单 Worker 顺序处理，队列为空后退出。
- 视频任务的采集和分析按任务重试规则处理；官方拉黑队列的网络、环境、登录、验证码或平台拦截失败项均保留原状态，不因开关切换或 Worker 轮询而静默重试，必须由用户显式点击“重试”或“恢复”。不通过更换身份或其他方式绕过平台控制。
- 本机服务提供一键启动方式，默认不写入 Windows 开机启动；同时提供 Docker Compose 部署配置，保持相同的服务接口和持久化模型。
- 浏览器和本机服务之间的最高测试 seam 是视频任务编排入口。该入口接收视频任务，协调采集器、AI 分析器、名单状态和拉黑队列，并输出可观察的任务结果。

## Testing Decisions

- 核心流程测试只验证外部行为和状态变化，不验证具体函数调用顺序或内部实现细节。
- 视频任务编排入口使用测试替身：测试采集器返回固定的一级评论、楼中楼、昵称和分页结果；测试 AI 返回命中、非目标、不确定和无效响应；测试拉黑执行器只记录要执行的 UID，不触碰真实 B 站账号。
- 编排测试覆盖：任务创建、完整性统计、断点恢复、批量分析、UID 去重、全局名单更新、证据保存、三态行为、样本版本引用、异常重试和暂停。
- 状态机测试覆盖：`hidden`、`review`、`queued`、`blocked`、`exception`、`failed`、`paused` 的合法转移，以及撤销和例外对后续同步的影响。
- 采集器适配测试使用固定的接口响应样本，覆盖分页、楼中楼、置顶评论、空页、重复页、部分失败和覆盖率计算；不把 B 站实时接口作为单元测试依赖。
- AI 适配器测试覆盖远程 OpenAI-compatible 响应解析、结构化结果校验、上下文预算降级、超时、重试、无效 JSON 和模型不可用时的规则降级。
- 样本管理测试覆盖文本框和文件导入、预览、去重、正例/反例标签、昵称样本、显著样例、版本发布、停用和历史任务版本留存。
- 插件过滤测试使用固定评论 DOM 样本，覆盖评论异步加载、楼中楼、已隐藏 UID、未知 UID、名单增量同步、服务断开后的缓存过滤和撤销。
- 管理页测试覆盖任务列表、任务详情、证据展开、复核操作、样本发布、UID 状态和拉黑队列状态的可见更新。
- 真实集成测试只在明确的测试账号和小规模测试视频上执行，用于验证 B 站会话同步、真实采集器、远程模型端点和原生拉黑界面适配；验证码或平台拦截出现时测试必须停止并记录。
- 浏览器端端到端测试覆盖普通视频页的任务提交、评论隐藏和本机服务连接；不测试弹幕，因为弹幕不属于首版范围。

## Out of Scope

- 不采集、分析或隐藏弹幕。
- 不支持动态、直播间、番剧页、移动端、App 或其他平台。
- 不自动举报、发私信、评论、关注、骚扰或组织围攻。
- 不做跨平台身份推断，不根据昵称以外的信息推断同一用户在其他平台的身份。
- 不把昵称字符串简单子串匹配当作完整的昵称语义判定。
- 不把外部 `bbc-skill` 作为不可替换的核心依赖，也不复制其与本项目无关的 Agent Skill 集成。
- 不使用隐藏接口、伪造请求、更换身份、代理池或其他方式绕过 B 站验证和反自动化控制。
- 不要求首版支持多账号、多浏览器内核、Windows 开机自启或公共云端 SaaS。
- 不对历史任务进行自动回溯重判；新样本和新规则只影响后续任务。
